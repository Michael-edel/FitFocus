# Решения по FitFocus

Обновлено: 09.10.2026. Область снимка: [документация](docs/README.md).

Этот журнал отделяет согласованное направление от фактической реализации.
«Согласовано, реализация ожидается» не означает, что решение уже работает.
Новая существенная договорённость оформляется новым ADR; старый документ
сохраняется со ссылкой на заменяющее решение.

| Решение | Статус | Основание и критерий реализации |
|---|---|---|
| D-001. Стабилизация до новых крупных функций | Согласовано | Сначала закрыть [P0](TASKS.md); затем расширять продукт |
| D-002. Сохранять локальное намерение при конфликте | Согласовано, реализация ожидается | 409 не является успешной синхронизацией; [модель](docs/sync-model.md) |
| D-003. Разделить владельца операции и сессию попытки | Согласовано, реализация ожидается | accountId постоянен; sessionEpoch защищает попытку и поздний ответ |
| D-004. Сохранить поколения удалённых серверных записей | Согласовано, реализация ожидается | Закрыть ABA через tombstone/монотонную версию; [модель данных](docs/data-model.md) |
| ADR-005. Одна outbox в IndexedDB | Согласовано; нормализатор реализован отдельно, полная очередь ожидается | [Полное решение и миграция](docs/adr/ADR-005-durable-outbox.md); Web Locks необязательны |
| D-006. Маленькие проверяемые изменения | Согласовано | Отдельные PR с явными зависимостями, CI на точном SHA, выпуск по чек-листу |

Нумерация ADR-005 продолжает согласованное обозначение решения об outbox.
D-001–D-004 — краткие записи этого журнала; отдельных ранее существующих
ADR с этими номерами в проверенном дереве не найдено.

## Что нельзя подменять при реализации

- Хранилище очереди не выбирается по наличию Web Locks.
- accountId legacy-операции не угадывается по текущему входу или глобальному ключу.
- Fingerprint не зависит от позиции записи и retryCount.
- Импорт и отметка migration item не расходятся по разным транзакциям.
- Полученный позже server snapshot не разрешает конфликт сам по себе.
- Успешный ответ старого запроса не подтверждает новую независимую правку.
- Обновление service worker не доказывает, что старая вкладка закрыла IDB.
- Новые JSON-обёртки и коды ошибок не объявляются действующим API до внедрения.
