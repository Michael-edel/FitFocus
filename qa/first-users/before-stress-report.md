# FitFocus — baseline 4, тестировщик на прочность
Дата: 2026-10-22. Только http://127.0.0.1:4254/. Chrome CUA. Пользователь first-user-4254@example.test. Код, чужие отчёты и находки не читались; продукт не изменялся.

## Итог
Первый успех достигнут. Обычные тестовые значения: вес 70 кг, рост 170 см, возраст 30, мужской, похудение, цель 65 кг, умеренная активность. Создан AI-план: 1800 ккал, 120 Б / 60 Ж / 195 У, дефицит 500 ккал/день. До reload — CLOUD: SAVED. После reload профиль и цель сохранились, приложение открыло Обзор. После повторного открытия локального сайта и раздела План те же KPI, меню и цель сохранились; CLOUD: IDLE. Это доказывает сохранение через UI в данной fixture, не реальную облачную синхронизацию.
Вернулся бы: НЕТ до исправления непонятной ошибки рисков.

## Сценарий и счётчик
Считаются явные клики по сайту; dblclick = 2. Ввод/замена поля = 1. Системные Back/Forward/reload и открытие вкладок отдельно. Автопрокрутка инструментов отдельно не считается пользовательским scroll.
1. Главная → Google профиль: 1 клик.
2. Fixture email корректно заменён fill на заданный: 1 ввод; продолжить: 1 клик.
3. Попытки setValue: вес -5, рост 0, возраст 999: 3 ввода. На экране вес/рост стали пустыми, возраст 999. Попытка нажать Создать: 1 клик по заблокированной кнопке (перехода нет).
4. Вес 70 и рост 170 через fill: 2 ввода. Создать AI-план dblclick: 2 клика. Появилась AI-инициализация с возрастом 999, затем ошибка рисков.
5. Browser Back → локальная fixture-форма; Forward → анкета. Возраст сброшен с 999 на 25.
6. Возраст заменён на 30: 1 ввод. Создать dblclick: 2 клика. Успех.
До успеха: 7 попыток клика (6 по активным кнопкам + 1 по заблокированной), 7 вводов, 0 явных scroll, Back 1, Forward 1. Всего 16 действий при включении двух навигаций.
7. Reload 1, затем План 1 клик. Вкладка была преждевременно закрыта до окончания загрузки плана — ошибка процедуры тестировщика, не дефект продукта. Открыта новая собственная вкладка на том же локальном URL, План ещё 1 клик; дождался KPI.
С полной проверкой сохранения: 9 попыток клика, 7 вводов, 0 scroll, Back 1, Forward 1, reload 1; 19 действий без открытия/закрытия вкладок. Открытие вкладок: 2; закрытие: 2. Обе свои вкладки закрыты, очередь свободна.
Инструментальная неудача: 1 fill с uppercase accessible name не нашёл поле (0 вводов); после DOM snapshot точное регистрозависимое имя исправлено. Это не дефект продукта.

## Ожидаемая валидация
V1. Пустые/неположительные базовые данные блокируют Создать AI-план. План с ними не создан. Значения -5 и 0 после setValue показались пустыми; сам приём именно отрицательного числа этим тестом не доказан.
V2. При валидном создании кнопка в инициализации disabled. Двойной клик не создал видимых дублей или двойного перехода; число сетевых запросов не проверялось.

## Дефекты и затруднения, привязка к странице
D1, существенный: анкета /, вес70/рост170/возраст999. Двойное Создать запускает AI-инициализацию вместо понятной ошибки диапазона возраста. Затем текст: «Для выбранной интенсивности требуется подтверждение „Я понимаю риски“». На полной форме нет видимого соответствующего чекбокса/действия, нет поля интенсивности дефицита; выбрана умеренная активность. Пользователь не понимает, как исправить. Screenshot image output S2 (ошибка) и AX с возрастом999 в инициализации. Источник серверной проверки в fixture неизвестен.
D2, небольшой: анкета / при пустых весе/росте — кнопка disabled без пояснений у полей, почему и какой диапазон допустим. Screenshot S1.
D3, небольшой: после Back к fixture и Forward в анкету несохранённый возраст999 заменился на25 без предупреждения о потере ввода. Screenshot S3. Для неверных данных это не блокирует восстановление, но черновик не сохраняется.
