# Текущее состояние FitFocus

Сверено: 12.10.2026. Этот файл — краткая точка входа в проект.
Порядок реализации и критерии готовности хранятся в [TASKS](../TASKS.md),
результаты конкретных проверок — в [журнале](stabilization-progress.md).

## Что это за проект

FitFocus — PWA для питания, привычек и прогресса. Основной цикл:
профиль и цель → персональный план → дневник и ежедневные действия →
обзор прогресса → корректировка плана. Есть рецепты, семейное меню,
список покупок, AI-анализ и рекомендации. Подробный перечень функций и
ограничений внешних интеграций: [PRODUCT](../PRODUCT.md).

Текущий приоритет — сохранность данных и воспроизводимый выпуск.
Крупные продуктовые улучшения идут после приёмки P0.

## Что завершено в текущем клиентском этапе

После этапа 15 state-ключей существующий профиль переведён на ту же
постоянную outbox. HTTP остаётся отдельным `/api/profile` с capability,
проверкой account/session и CAS. Две быстрые правки сохраняются последовательно;
409 сохраняет локальное намерение без автоматического rebase.
Auth/access/protocol-пауза не запрещает новые локальные commit.

Guarded refresh не заменяет pending-профиль или несохранённую форму.
Поздний ответ проверяется по поколению входа и счётчику правок; чистый refresh
меняет только редактор профиля. Отказ commit сохраняет dirty-черновик и
доступную кнопку сохранения после reload. Исправлена гонка времени retry/finish.
Регистрация создаёт профиль с canonical account и baseVersion=0 до AI-запроса;
AI-update продолжает ту же причинную цепочку. Ошибка commit оставляет форму
открытой. Own IDB-profile восстанавливается без OAuth-маркера, email-подбора
и переноса prefix. Invite redeem проверяет свежую сессию до расходования кода.
Sender останавливается при pagehide; BFCache-возврат заново проверяет сессию
исходного аккаунта. Последняя локальная сверка: 817 unit-тестов и 20 повторных
браузерных сценариев, без retries. Полная матрица, typecheck/guards и границы
mock-проверки — в журнале. Это граница предыдущего этапа `cb6e6cf`.

На `dac2de2` добавлены guarded bootstrap/state-hydration и атомарный
auth-fence для hydrate/profile seed. Отказ `/me` больше не допускает вход
через общий local fallback; временная недоступность сохраняет чтение
собственных данных. Повторный идентичный снимок второй вкладки сохраняет
revision, новая версия всё равно защищает независимый редактор от перезаписи.
Полная локальная матрица выявила нестабильный profile Save на iPhone PWA.
После десяти успешных диагностических повторов прогон Safari/PWA с двумя
workers дал 18 passed / 2 failed. В одном падении pointerdown попал в Save,
а через 12 мс pointerup/click — в DIV; операция и PUT не создавались.
Это подтверждает потерю клика при смене цели. Регрессионный тест отдельно
воспроизвёл сдвиг документа при исчезновении notice: 86/86/106 px на
Chromium/Firefox/iPhone PWA. На `3550cc8` высота области сохраняется до
завершения жеста; семь проектов и 20 Safari/PWA повторов прошли.
Полная матрица исправления: 151 passed / 1 failed / 9 skips. Все новые
сценарии прошли; profile-conflict на iPhone Safari упал после функциональных
проверок на сообщении `/api/me due to access control checks` при reload.
[CI опубликованного исправления `45315d9`](https://github.com/Michael-edel/FitFocus/actions/runs/38172605267)
прошёл: 846 unit, 152 browser passed / 9 skips, без flaky. Второе историческое падение:
console `/api/me due to access control checks` при reload; причина не установлена.
CI регистрации выявил похожее сообщение для `/api/profile`; объединять
эти случаи до проверки трасс нельзя. [Результаты и границы](stabilization-progress.md).
Это не завершение runtime legacy-миграции или выпуска.

## Что делаем дальше

1. Завершить приёмку [bootstrap/hydration](bootstrap-hydration.md#приёмка-компонента-и-оставшаяся-работа),
   проверив полный набор после исправления Save и разобрав Safari page errors при reload;
   затем остальные family/AI callbacks и cache с привязкой к исходной сессии.
   Не выдавать сохранение профиля за подтверждение всей очереди.
2. Подключить runtime-импорт legacy с доказанным владельцем и фактической
   остановкой старых writers. Проверить старую и новую сборки на одном origin.
3. Завершить UI повтора и разрешения конфликтов, backup, экспорт и очистку
   всех stores без потери ожидающих операций.
4. Пройти полную матрицу lifecycle, staging и выпуск через защищённую main.
