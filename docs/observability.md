# Наблюдаемость FitFocus

Снимок: 09.10.2026, `810adb1`. [Область документации](README.md).

## Что есть в коде

`functions/api/_lib/observability.ts` создаёт или принимает безопасный
request ID, добавляет `X-Request-ID` в ответ и пишет JSON-события.
State/profile используют события ответа со status и requestId.
Есть отдельные AI telemetry, health/admin и push-модули. Это не подтверждает
полный охват всех routes, настроенный dashboard или работающие alerts среды.

`external_fetch.ts` ограничивает ожидание fetch через AbortController;
эта граница сама по себе не измеряет весь пользовательский сценарий.

Для каждой метрики определить точку записи, единицы, отсутствие двойного
учёта при retry, хранение и способ просмотра. Числовые SLO/пороги не выбраны:
сначала нужен измеренный исходный уровень. Реализация и подключение сигналов
закрываются отдельными пунктами задач, а не одной таблицей документации.

## Безопасные события

Допустимы тип операции, статус, длительность, технический код причины,
версия схемы/сборки и неприватный корреляционный ID. AccountId/opId пригодны
для локальной диагностики; их отправку в telemetry нужно отдельно определить.

В события не включать payload профиля, дневник, фотографии, email, токены,
cookie, секреты, push endpoints и rawRecord карантина. Request ID связывает
клиентскую ошибку с сервером, но не является ключом авторизации или idempotency.

## Проверка после изменения

Воспроизвести штатный путь, timeout, auth-паузу, конфликт и storage failure.
Проверить, что каждый путь даёт различимое событие без пользовательских данных,
а повтор и восстановление не искажают счётчики. Для выпуска записать фактически
доступные панели/события и результаты в [чек-листе](../RELEASE_CHECKLIST.md).
