## Проблема и границы

В mock-сценариях WebKit поздний `/api/me` может попасть в preview proxy при
закрытии контекста, когда маршруты Playwright уже снимаются. Функциональные
assertions проходят, но preview получает `ECONNREFUSED` от отсутствующего
backend. Явное закрытие страницы в прежней диагностике не помогло.

Проверяется выгрузка настоящего документа через переход на `about:blank`
до закрытия контекста, пока mock-маршруты ещё существуют. Фильтрация логов,
подавление API и синтетические события не считаются исправлением.

Рабочая общая фикстура размещена в [mockTest](../e2e/support/mockTest.ts) и подключена
к 12 mock-наборам. Перед выгрузкой упавшего сценария она прикладывает снимок
страницы. В storage-тесте вторая вкладка выгружается перед своим явным close.
Четыре native PWA-набора сохраняют обычную фикстуру Playwright: их реальный
SW/HTTP/lifecycle нельзя подменять этой проверкой mock-маршрутов.

## Следующие критерии приёмки

- Сохранять полную проверку общей фикстуры при изменении mock-наборов.
- Сохранять исходный неуспешный результат даже при успешном повторе;
  прежняя задержка приложения не объясняется одним зелёным прогоном.
- Подтверждать CI точного SHA каждого следующего изменения.
- Проверять функциональный итог и proxy-логи отдельно; native PWA,
  реальный OAuth, BFCache и staging требуют собственных доказательств.

## Недельные семейные сценарии и reload-проба WebKit

В CI #1465 weekly-shopping тест для iPhone Safari получил ответ HTTP 200 с
`week_start=2026-10-26`, но тело содержало старую mock-запись. Тест менял
переменную mock-недели уже после сдвига browser clock, поэтому автоматический
запрос мог обработаться до обновления fixture. Теперь тесты заранее задают
ответ для будущей недели, потом двигают часы; context, shopping response и
shopping check прошли 9/9 на iPhone Safari без retries.

В desktop WebKit account-switch тест зарегистрировал console error для
`/api/state` после reload экрана прогресса. Trace CI не показывает завершённого
запроса к этому пути. После reload тест теперь ждёт пустую durable outbox, а при
повторном сбое прикладывает location console-сообщения и детали requestfailed.
Локальный целевой тест прошёл 3/3 без retries; причину исходного сообщения
проверит точный CI следующей ревизии. Это mock browser evidence и не заменяет
staging или реальный OAuth.
