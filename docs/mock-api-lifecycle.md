## Проблема и границы

В mock-сценариях WebKit поздний `/api/me` может попасть в preview proxy при
закрытии контекста, когда маршруты Playwright уже снимаются. Функциональные
assertions проходят, но preview получает `ECONNREFUSED` от отсутствующего
backend. Явное закрытие страницы в прежней диагностике не помогло.

Проверяется выгрузка настоящего документа через переход на `about:blank`
до закрытия контекста, пока mock-маршруты ещё существуют. Фильтрация логов,
подавление API и синтетические события не считаются исправлением.

Рабочая общая фикстура размещена в [mockTest](../e2e/support/mockTest.ts) и подключена
к 12 mock-наборам. Перед выгрузкой упавшего сценария она прикладывает снимок
страницы. В storage-тесте вторая вкладка выгружается перед своим явным close.
Четыре native PWA-набора сохраняют обычную фикстуру Playwright: их реальный
SW/HTTP/lifecycle нельзя подменять этой проверкой mock-маршрутов.

## Отдельная native PWA-диагностика

В скачанном trace CI `5b90249` зафиксирован pageerror из старого sender
(`drain`) после нажатия обновления, до окончания reload; это не только
console warning и не доказанная ошибка конфигурации CORS.
Внешняя native HTTP/SW-проверка удержала старый семейный PUT во время
явного обновления и прошла 1/1 на desktop WebKit, без retries: запрос закрылся,
opId остался, pageerror отсутствует. Лог `native-unload-held-v2.log`.
Первый вариант диагностики остановился раньше на предусловии с дефолтными
5 с; затем приведён к настройкам проекта 10 с и ожиданию самого экрана.
Оба лога сохранены. Ошибка CI этим не воспроизведена и не считается исправленной.
